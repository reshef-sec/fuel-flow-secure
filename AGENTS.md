- No createServerFn/app-server code: backend logic lives in external-DB security-definer RPCs (src/lib/backend.ts) and the admin-accounts DB function, because the app must also deploy as a static Netlify SPA (STATIC_SPA build flag in vite.config.ts).
- Public employee routes bypass all staff redirects, including mandatory password changes; sharing uses the current browser origin and anonymous data access stays behind token-scoped verification RPCs, never direct voucher-code SELECT.
- Employee issuance uses issue_voucher_to_worker (DB picks/locks matching cards with canonical fuel/branch rules mirrored in src/lib/issuanceStock.ts and inserts the link in one transaction); physical allocations use transfer_voucher_stock; neither falls back to client upserts when the RPC is unavailable.
- Issuance RPC returns a safe JSONB envelope with persisted link_id, total and vouchers; issuanceResponse validates it before exposing the link, accepts the legacy row array during rollout, and never returns confidential code columns. Database issued status maps to the existing employee-issued display status.
- Employee issuance reloads physical stock for every role; imports use the admin-guarded store_voucher_codes RPC so confidential code columns need no client SELECT grant.
- Dashboard and central allocation totals use the shared get_central_inventory_summary database RPC, refresh on entry/focus/interval and after successful writes, and never fall back to saved budgets or client sums; exact voucher selection still checks physical stock and awaits transfer persistence.
- Inventory summary hooks keep page-local state, expose the shared derived totalAvailableBalance and ignore superseded responses; allocation dialogs explicitly refresh the parent after each saved fuel transfer so old requests cannot restore a pre-allocation balance, including partial success.
- User display resolves authenticated profiles and matching live app-user names through userDisplay helpers; useCurrentUser must never impersonate a role-preview account.
- Display dates through israelDate helpers and localized ISO-backed inputs; keep stored/filter date values in ISO format to preserve sorting.
- Exact voucher combinations use the browser-safe inventorySelection module so physical selection can be regression-tested without importing UI or database clients.
- Branch terminology and assignment suffixes use branchLabels presentation helpers; preserve legacy stored pool identifiers, transfer targets and authorization checks rather than renaming stock for a UI-only change.
- Development tools use external database RPCs pinned to a single installer-verified immutable owner UUID plus the protected admin role; client rendering fails closed until that RPC verifies the active identity, preventing name spoofing or role-preview access.
- Vehicle snapshot imports, stock insertion and Paz reconciliation use awaited external-database RPCs with transactional audit logging; stock never upserts existing cards, client sync preserves inactive history, and issuance verifies active clients in both Data API queries and a database trigger.
